# Data Sheet Editor

Редактор листов технических данных КИП. Многофайловый сайт: `index.html`,
`styles.css`, `app.js`, `xlsx.js`, данные `seed.json` + собранный из него
`seed.js` и рисунки в `img/`. Открывается локально из этой папки без сборки.

Стиль: голубой/белый с розовыми акцентами. В интерфейсе только левая панель
(проекты + листы) и рабочая область листа; правой панели нет.

## Проверка

```text
multitool-node --skill websites site.cjs check index.html
multitool-node --skill websites verify.cjs index.html --actions actions.json
```

`seed.json` — данные 17 приборов книги «Все листы тех. данных.xlsx», рисунки
лежат отдельными файлами в `img/`. `seed.js` — тот же JSON в обёртке
`window.DS_SEED = …;`, чтобы страница работала и по `file://` без сервера.
После правки `seed.json` пересоберите обёртку:

```text
python tools\make_seed_js.py
```

Выгрузка Excel берёт рисунки по путям через `fetch`, поэтому работает на сайте
и локальном сервере; при открытии по `file://` рисунки в книгу не попадут.

Пересобрать данные из эталонной книги:

```text
python tools\extract_seed.py
python tools\upgrade_seed.py
python tools\split_images.py
```

`extract_seed.py` собирает `seed.json`, `upgrade_seed.py` добавляет геометрию
рисунков и таблицы комплектов, `split_images.py` выносит рисунки в `img/`,
делает `seed.json` компактным и пересобирает `seed.js`.

## Перевод

`translate.js` — офлайн-перевод RU→EN: без сети и внешних сервисов. Словарь
`dict.js` собран из RU/EN-пар `seed.json` плюс глоссарий, свои пары
пользователя лежат в `localStorage` (`ds-editor-gloss-v1`) и важнее словаря.

Движок работает в четыре слоя: точная пара → основа фразы (окончания
отрезаются) → шаблон с числами → разбор по кускам. Благодаря шаблонам пара
`2-х проводная, Pt100` → `2-wire, Pt100` переводит и `3-х проводная, Pt100`,
и `3-проводная, Pt100`, а `Pt100`/`316L` остаются как есть. Слова без перевода
показываются в панели перевода подсказкой «Нет перевода: …» — клик открывает
глоссарий с заполненным русским термином.

```text
multitool-node tools\test_translate.cjs
```

## Модель

```
project { id, name, devices[] }
device  { id, no, suffix, titleRu/En, scopeRu/En, introRu/En,
          columns[{id, name}],
          rows[{id, labelRu/En, rowSpan, cells[{id, span, ru, en}]}],
          figures[], markings[], tagGroups[],
          kits[{ id, titleRu/En, introRu/En, columns[], rows[], figures[] }] }
```

- `columns` — колонки значений: исполнения/датчики (у Тесей ТСПТ их 4).
- `cells[].span` — сколько колонок занимает объединённая ячейка; сумма span
  равна числу колонок.
- Колонку можно добавить, переименовать и удалить; при удалении значения
  колонки удаляются, а объединения пересчитываются.
- Ячейку можно объединить со следующей и разъединить; строки добавляются,
  удаляются и двигаются.
- `kits` — комплекты прибора (гильза или манифольд): своя таблица
  характеристик и рисунок, отдельные страницы RU/EN после страниц прибора.
- `rowSpan` — минимум высоты строки: в Excel строка растягивается, если подпись
  или значение не влезают в одну строку.
- RU/EN/TAG — страницы одного листа. Правка RU и EN идёт в одних и тех же
  строках.

## Эталон и восстановление

- Проект **«Все листы»** — эталон. Он защищён от правки: поля только для чтения,
  структурные кнопки выключены. Включить правку можно кнопкой **«Редактировать
  эталон»** в баннере над листом — только после подтверждения в диалоге.
  Та же защита закрывает удаление/переименование эталонного проекта и удаление
  его листов.
- Кнопка **«Привести к эталону»** в шапке листа заменяет текущий лист эталонной
  версией (таблица, колонки, рисунки, маркировка, теги, комплекты) с
  подтверждением. В проекте источник — проект «Все листы»; в самом эталоне —
  встроенная копия `seed.js`, поэтому испорченный эталонный лист можно вернуть
  к исходному виду.
- Подтверждения «Привести к эталону» и «Редактировать эталон» идут через
  встроенный диалог `#confirm-dialog`, а не `window.confirm`.

## Сохранение

Состояние (все проекты и листы) хранится в браузере и сохраняется после
создания проекта: запись идёт в **IndexedDB** (`ds-editor/state/current`), а
параллельно — в `localStorage` (`ds-editor-v1`) как быстрый кэш. Вместе с
состоянием пишется метка времени (`ds-editor-v1-at` и `state/current-at`).

Загрузка при старте: мгновенно показывается копия из `localStorage`, затем
асинхронно читается IndexedDB и **подменяет состояние, только если там снимок
новее** (или в `localStorage` ничего нет) и пока пользователь ничего не менял.
Так устаревшая копия в `localStorage` (например, после переполнения его квоты
рисунками) больше не затирает свежие данные из IndexedDB. Дополнительно
запрашивается `navigator.storage.persist()`, чтобы браузер не вытеснял данные.

Файл проекта на диске:

- **«Сохранить»** (или **Ctrl+S**) — если файл уже связан, перезаписывает его
  на месте, без папки «Загрузки». Файл не выбран — открывает системный диалог
  «Сохранить как».
- **«Сохранить как»** — выбрать новый файл `*.json` (Chrome/Edge, File System
  Access API). В Firefox/Safari вместо диалога файл скачивается, как раньше.
- **«Открыть»** — открыть файл проекта с диска (текущая работа в браузере
  заменяется после подтверждения).
- Связь с файлом запоминается в IndexedDB (`state/file-handle`): после
  перезагрузки имя файла видно под кнопками, а права на запись браузер
  запрашивает одним подтверждением при следующем сохранении.
- Если браузер не даёт сохранять (песочница предпросмотра), внизу панели
  появляется красное предупреждение.
- Данные привязаны к браузеру и адресу страницы: при открытии через предпросмотр
  с новым портом сохранённое состояние не видно, поэтому файл — самый надёжный
  вариант.

## Excel

`xlsx.js` собирает OOXML + ZIP без внешних библиотек. Один проект = один лист
книги. На прибор: RU-страницы, EN-страницы, TAG-страница, затем страницы
комплектов. Сетка A–Z, 60 строк на страницу, рамка E2:Y59 (medium), тонкие
границы таблицы, ширины 22/33/21 px, строки 21 px, A4 книжная, масштаб 89 %,
разрывы каждые 60 строк и перед AA, область печати A1:Z…, страничный режим,
рисунки по центру с сохранением пропорций.

Высота строки таблицы подбирается по тексту: если подпись или значение не
влезают в одну строку, строка растягивается на две и больше (`rowSpan` из
данных работает как минимум). Блок «подводка + рисунок + подпись» не режется:
если рисунку пришлось бы ужаться больше чем на 3 строки, блок целиком уходит
на следующую страницу листа — с подводкой, подписью и своим номером
(продолжение в духе страниц `figs` эталона). Число физических страниц листа в
RU и EN выравнивается, поэтому номера совпадают.

Нумерация: `[прибор].[исполнение]` (`2.1`), при нескольких страницах в языке —
`[прибор].[исполнение].[страница]` (`6.1.1`, `6.1.2`, `6.1.3`). Номера идут
подряд по физическим страницам: сначала все RU, затем все EN, затем TAG.


Проверка выгрузки без браузера:

```text
multitool-node tools\test_export.cjs
```

## Файлы
